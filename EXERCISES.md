# Exercises for chapter "110 - Spring Data JPA"

So far, the pizza app stores products, customers and orders with hand-written JDBC code
(`JdbcProductRepository`, `JdbcCustomerRepository`, `JdbcOrderRepository`). In this exercise you
replace this code with Spring Data JPA.

The tests under `src/test/java` pass on this branch. Run them after every step: in the end they
must pass with JPA just the same.

The database schema in `schema.sql` stays unchanged. So your entities have to match the existing
tables and columns, not the other way round.

## a) Build file and configuration

In the `pom.xml`, replace the starter `spring-boot-starter-jdbc` with
`spring-boot-starter-data-jpa`. Why is the JDBC starter no longer needed afterwards?

Add to `application.properties`:

````properties
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=true
````

With `validate`, Hibernate does not create its own schema but checks at startup whether your
entities match the tables from `schema.sql`. If something doesn't match, the application does not
start, and the error message names the table and column. With `show-sql` you see the SQL that
Hibernate generates.

## b) Products

Turn `Product` into a JPA entity. Keep in mind:

* The table is called `products`, the column for the id is called `pk`.
* JPA needs a no-argument constructor (it may be `protected`) and cannot populate `final` fields.

Rewrite `ProductRepository` so that it extends `JpaRepository`. Which of the methods declared so
far can you then delete from the interface?

Then delete `JdbcProductRepository` and `HashMapProductRepository`.

## c) Customers

Turn `Customer` into an entity and `Address` into an `@Embeddable`. The address has no table of its
own, its fields are columns in `customers`.

The id of a new customer is assigned by the database (`GENERATED BY DEFAULT AS IDENTITY`). Choose
the matching `@GeneratedValue` strategy.

`CustomerRepository` extends `JpaRepository` as well. The method `findByPhoneNumber` stays: Spring
Data derives the query from the method name.

Delete `JdbcCustomerRepository` and `HashMapCustomerRepository`. What about the no-argument
constructor of `CustomerService` afterwards?

## d) Orders

Turn `Order` into an entity. The table is called `orders`, because `ORDER` is a reserved word in
SQL.

An order belongs to exactly one customer. Map this with `@ManyToOne`; the foreign key column is
called `customer_id`. The field `estimatedTimeOfDelivery` is stored in the column `eta`.

Delete `JdbcOrderRepository`. The `setId` methods in `Customer` and `Order` and the constructors
with an id parameter were only needed by the JDBC code; they can go.

Start the application (`PizzaApp`) and call `GET /orders` and `GET /customers`. Look in the log at
the SQL that Hibernate issues for them.

## e) Bonus: custom queries

Add to `OrderRepository`

* a derived query that returns all orders of a customer by their phone number (hint: queries can
  follow associations, `findByCustomer...`), and
* a query with `@Query` in JPQL that sums up the total revenue of a customer.

Offer both as methods in `OrderService` and check them with a test.

## f) Bonus: projection

A phone list only needs the name and phone number of the customers. Create a record
`CustomerContact` for this and add a method to `CustomerRepository` that returns all customers
sorted by name as `List<CustomerContact>`.

What SQL does Hibernate issue for this, compared with `findAll()`?
